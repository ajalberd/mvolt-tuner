Setup & Run Results Knob importance

1Your limits

The only ceilings the tuner respects. Clock offsets have no caps of their own: how far they go depends on voltage, and crashes teach the tuner which combinations to stop trying. Leave a field empty for no limit.

How they are enforced

Power: your limit becomes the card's own watt cap on every trial, so it runs at full speed inside your budget. Above stock it raises the card's power limit (up to the card maximum). If the measured average still goes more than 5% over, the run is stopped.
Voltage (core and fabric): right after each config is applied (before any load), the tuner reads each rail's effective voltage limit from mVolt+. Above your max, it puts your settings back immediately and skips that config. A limit above stock lets the sweep raise voltage; above 1.15 V the tuner uses mVolt+'s XOC range.
Configs that break a limit are never recommended, and are re-tested if you change the limits.

!Crash log

Hard freezes (black screen, fans at max, manual reset) are the dangerous ones: the run stops until you reset the PC. For each, the likely culprits are the settings that went beyond anything that has run clean. The hard-crash guard never applies a config at or beyond all of a freeze's culprit values. Driver resets recover on their own and only rule out configs at least as aggressive in every setting.

3What to test

The tuner does the stepping. Explore spreads runs across wide ranges to measure how much each control moves score, watts and stability. Edge search then finds the highest stable core for each power budget and undervolt level by halving the gap between pass and crash. Confirm backs the best off a safety margin and re-runs it several times before anything is recommended.

Edge search plan

Each lane is one power budget × one undervolt level. In each lane the tuner finds the highest stable core by halving the gap between the highest pass and the lowest crash (one step = 15 MHz). Results are shared: a pass with more voltage or budget counts as a pass with less (deeper undervolt / lower budget); a crash with less voltage counts as a crash with more. On this card a deeper undervolt holds more core, not less. Each lane starts where a crash model fitted to all your runs so far predicts ~10% crash chance, and never jumps more than 2 steps above its highest pass. A crash counts for every budget (they hit seconds into the load, before any cap binds). After 2 driver resets in one boot the run stops and asks you to restart Windows: on this card every hard freeze came after repeated resets. Press Start after the restart to resume.

REL (the voltage limit) only caps the top of the V/F curve. At a power budget the card runs below that top, where REL does nothing. The core voltage-demand offset lowers the voltage asked for at every clock - fewer watts, or more clock inside a binding budget. It can fail at any clock, so each config walks down from 0 one value at a time (0 is re-measured for a same-session comparison), and the first crash ends that config's lane. The 2-resets-per-boot stop applies as always.

The memory offset sweep steps up from the config's own memory offset the same way: the first value is re-measured as the reference, and the first crash ends the lane.
